# More data to match failed transactions & various bug fixes

Every result now carries its OPI request ID, and `repeatLastMessage()` tells you which original transaction it refers to, so interrupted payments, refunds and reversals can be matched and resolved reliably. This release also fixes terminal information, empty reprints and the merchant reference.

## New

- `OpiResult.requestId` and the `requestId` of the `Started`, `Connected` and `Completed` events return the OPI RequestID of every call, including failed and unknown outcomes. It is available from the `Started` event, so it can be stored with the transaction before the outcome is known.
- `repeatLastMessage()` returns `originalHeader` whenever the terminal provides it: the RequestID, RequestType and WorkstationID of the last payment, refund or reversal, with its original result (`overallResult`, `status`, `errorCode`). Match it to the original transaction's `requestId` before using its outcome.
- `refund(PaymentRequest)` starts an unreferenced refund with an optional merchant reference.

## Fixed

- `info()` returned no terminal information on terminals that send it as an info receipt, such as the RX5000. The receipt is now returned in `receipts.merchantReceipt` and `receipts.serviceReceipts`, and `result.terminal` is filled with terminal ID, model (`hardware`), firmware, serial and part number, IP and MAC address, app and EP2 version.
- `repeatLastMessage()` reported the original transaction's result as its own status, so a working recovery could show as an error. Its status now describes the RepeatLastMessage command; the original outcome is in `originalHeader`.
- A TicketReprint or GetInfo that the terminal reports as successful without sending any output was returned as a success. With `Available` receipt handling it now returns `TERMINAL_ERROR` with `NO_RECEIPT_RETURNED` or `NO_INFO_RETURNED`.
- The merchant reference is sent as `POSdata/MerchantReference` and accepts 1–40 letters, digits, `_` and `-`.
- `result.terminal` includes `stan` from the terminal's response.
- Diagnostics log the request ID and the original header.
